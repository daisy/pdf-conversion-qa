The DAISY Consortium PDF Conversion Quality Framework describes a transparent, repeatable and extensible methodology for evaluating services that convert PDF documents to structured documents. It assesses the accuracy, completeness and quality of each service by comparing its output against verified reference materials, so that organizations producing accessible publications can make evidence-based decisions about which conversion services to use.

This is a Working Draft. It was developed in consultation with the DAISY Consortium AI Special Interest Group. Comments are welcome as issues on GitHub.

Overview

The DAISY Consortium is developing a methodology to evaluate PDF to structured document conversion services. The purpose is to assess the accuracy, completeness, and quality of various conversion methods by comparing their outputs against verified reference materials.

Many DAISY Consortium members convert PDF source documents to more accessible versions (DAISY format, EPUB, Word, HTML) or alternative formats (audio, braille) of publications for people with print disabilities. These publications are diverse, but include textbooks, novels, journal articles, and other materials.

The methodology is intended to be a transparent, repeatable, and extensible process that can be regularly refreshed as new services and techniques become available. The results can be used to make evidence-based decisions on which services are integrated into DAISY production tools and to assist members in choosing which conversion services to use.

Evaluation Methodology

Reference Materials

The evaluation process uses two key reference documents:

Reference PDF
A carefully selected source document containing diverse content types that commonly appear in publications, including headings, images, lists, tables, mathematical expressions, footnotes, and text in multiple scripts.
Ground Truth Document
A manually converted and thoroughly proofread version of the reference PDF, which serves as the verified standard for comparison. This document has been quality-assured to ensure accuracy and completeness.

Evaluation Process

Each conversion service being evaluated will process the reference PDF to produce a structured markdown document. These converted versions will then be systematically compared against the ground truth document using the evaluation criteria detailed below.

Evaluation Criteria

The evaluation framework encompasses three main categories: conversion and markup quality, generated content, and standards compliance. These criteria were developed in consultation with the DAISY Consortium AI Special Interest Group.

Conversion and Markup Quality

Latin Script Extraction

  • Does the conversion process accurately extract all text in the Latin script, including accented and special characters?
  • Does the process accurately recognize all text in the Latin script, including accented and special characters from a scanned PDF?

Non-Latin Script Extraction

  • Does the conversion process accurately extract all text in non-Latin scripts (Arabic, Hanzi, Cyrillic, Devanagari, etc.)?
  • Does the process accurately recognize all text in non-Latin scripts (Arabic, Hanzi, Cyrillic, Devanagari, etc.) from a scanned PDF?
  • Is text correctly extracted from documents containing multiple languages, including where scripts change mid-paragraph?
  • Is text in right-to-left scripts (Arabic, Hebrew) extracted in the correct reading order?
  • Is text in vertical writing modes (top-to-bottom, as used in Japanese and traditional Chinese) extracted correctly?
  • In documents mixing horizontal and vertical writing modes, is text in each section extracted according to its own writing direction?

Document Structure and Organization

  • Is content presented in a logical reading order that reflects the document's structure?
  • Are unnecessary elements, such as running headers and footers, correctly ignored?
  • Are heading levels properly identified and maintained?
  • Are print page numbers included correctly?

Text Markup

  • Are list structures (ordered, unordered, nested) properly identified and marked up?
  • Are semantic elements such as block quotes, and asides appropriately marked up?
  • Is text formatting (bold, italic, underline, superscript, subscript) recognized correctly?
  • Are different languages within the document correctly identified and marked up?

Hyperlinks

  • Are plain hyperlinks correctly marked up?
  • Are embedded hyperlinks (URLs with link text) correctly marked up?

Specialized Content

  • Are footnotes and endnotes handled appropriately?
  • Are mathematical expressions converted accurately to LaTeX or MathML?

Images and Tables

  • Are images extracted cleanly without distortion or inappropriate cropping?
  • Are any existing alternative text descriptions preserved?
  • Are decorative images correctly identified?
  • Are captions for images and tables correctly identified?
  • Are tables converted accurately while maintaining their structure and cell relationships?

Metadata

  • Is existing document metadata correctly transferred from the PDF?

Generated Content

  • Are suitable alternative text descriptions generated for non-decorative images without alt text?
  • Is generated metadata complete and accurate?

Standards Compliance

  • Does the output validate against the target format's standards?

Test Management and Reporting

There is a wide range of commercial and open-source tools and services that could help manage the evaluation tests and to generate the reports. This approach should enable systematic tracking of conversion service performance over time and facilitate data-driven comparison across multiple services and versions.

Outcomes

This evaluation process will provide valuable insights into the strengths and limitations of current PDF conversion technologies. The results will help organizations make informed decisions when selecting conversion services and will identify areas where further development is needed.
